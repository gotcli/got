# Changelog

## v1.1.0 (unreleased)

### Upgrading from v1.0.4

Projects you already generated are never changed by installing a new GOT.
To pick up fixes in generated code, run inside each service or workspace root:

```sh
got upgrade --dry-run   # review
got upgrade             # refuses files with uncommitted Git changes
git diff
```

This fixes `.gitignore` (see Fixed) and makes `ConnectDB` return an error. Code
you changed yourself is reported as a manual step and left untouched.

### Changed (output of new projects)

- **Workspace layout.** `got init workspace` now places services under
  `services/`, Compose configuration in `deploy/compose.yml`, and shared logging
  and middleware in a `libs/` module. Use `--shared-module` and
  `--shared-version` when the shared module lives in its own repository.
  Workspaces created by v1.0.4 keep their layout: `got add service` adds new
  services at the workspace root, as before.
- **CRUD responses.** Code from `got generate crud` and `init --generate-crud`
  now uses request models with validation, so for newly generated tables:
  - `GET /` returns a page `{items, total, limit, offset}` instead of an array
    (`?limit=` defaults to 20, maximum 100).
  - `PUT /:id` (and the new `PATCH /:id`) is a partial update; omitted fields
    keep their stored value.
  - `DELETE /:id` returns `204`, and `404` for unknown ids.
  - Invalid bodies return `422` with per-field messages; unknown JSON fields
    return `400`.

  Endpoints generated earlier are not changed.
- **Database startup.** Generated services exit with a readable error instead
  of panicking when the database is unreachable (blueprints v0.3.0).
- New projects include `got-project.json`, which records the GOT version,
  module, architecture, and database.

### Added

- `got init --architecture hexagonal` (PostgreSQL): ports and adapters layout
  with domain unit tests, a migration runner (`go run ./cmd migrate`), and
  support in `generate crud`, `add swagger`, and `add auth`.
- `got add migration <name>` for hexagonal projects.
- `got generate crud --tables a,b` and `--dry-run`; `go mod tidy` now runs
  after generation.
- `got routes`: lists routes with handler and source location, and fails on
  duplicate routes.
- `got config`: effective configuration with its source; secrets are masked.
- `got upgrade`: applies fixes to projects generated by older versions.
- Non-interactive use: without a terminal, or with `--no-input`, GOT lists the
  missing flags instead of prompting. `GOT_DB_PASSWORD` supplies the CRUD
  inspection password.

### Fixed

- **Secrets could be committed.** The generated `.gitignore` had indented
  patterns, which Git does not match, so `config.yml` (with `DB_PASSWORD`) and
  `logs/` were not ignored. Check that `config.yml` was not committed in
  existing projects, and run `got upgrade`.
- Columns with a database default (for example `active boolean DEFAULT true`)
  were overwritten by the Go zero value on insert.
- Generated CRUD for tables with `numeric` columns failed to build until
  `go mod tidy` was run manually.
- PostgreSQL identity and SQL Server `IDENTITY` primary keys were required in
  create requests.
- New workspaces failed to build because services required an unpublished
  version of the shared module.
